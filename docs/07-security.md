# 7️⃣ الأمان (Security)

هذا الملف يصف **ما هو مطبّق فعلاً في الكود**، ثم القيود المعروفة، ثم توصيات للتحسين.

---

## 1. ما الذي يحتاج حماية؟

| الأصل | لماذا يهم؟ |
| :--- | :--- |
| لوحة الإدارة | تغيير محتوى الموقع، قراءة الرسائل، رفع ملفات |
| رسائل الزوار | بيانات شخصية (أسماء وبريد) |
| أسرار `.env` | توكن البوت، كلمة مرور SMTP، توكن GitHub (اختياري)، كلمة مرور الإدارة |
| خدمات خارجية (Telegram/SMTP) | يمكن إساءة استخدامها (إغراق رسائل) |

---

## 2. الضوابط المطبّقة

### 2.1 المصادقة والجلسات
| الضابط | التفاصيل |
| :--- | :--- |
| لا كلمة مرور افتراضية | الدخول بكلمة المرور يعمل فقط إن ضُبط `ADMIN_PASSWORD` |
| مقارنة بزمن ثابت | `crypto.timingSafeEqual` في كلمة المرور والرمز والتوقيع |
| رموز OTP | 6 أرقام بـ `crypto.randomInt`، 10 دقائق، استخدام واحد، لا تُكتب في السجل ولا تُعاد في الاستجابة |
| جلسة موقّعة | HMAC-SHA256 على وقت الانتهاء، **ساعتان** |
| مفتاح التوقيع | `SESSION_SECRET` (ثم `ADMIN_PASSWORD`، وإلا عشوائي عند كل إقلاع) |
| تخزين الجلسة | في ذاكرة الصفحة فقط (لا `localStorage` ولا ملفات تعريف ارتباط) |
| بلا CSRF | الجلسة ترسل في ترويسة `Authorization` وليس في Cookie |

### 2.2 التحكم بالوصول
كل المسارات الإدارية خلف `requireAdmin` (انظر جدول المسارات في `03-backend-api.md`). المسارات العامة فقط: قراءة المحتوى، نموذج التواصل، تنبيه الزيارة، طلب/تحقق الدخول.

### 2.3 تحديد معدل الطلبات
لكل IP ولكل مسار (الدخول، OTP، التواصل، الزيارة، تحليل السيرة) — انظر الجدول في ملف الـ API.

### 2.4 حماية البيانات المدخلة
| الحماية | أين |
| :--- | :--- |
| حدود حجم الجسم (1MB عام، 8MB للصور، 15MB لتحليل السيرة) | `express.json` |
| تحقق وحدود طول لحقول التواصل + صيغة البريد | `POST /api/contact` |
| `escapeHtml` على نصوص الزائر قبل إدراجها في Telegram/HTML للبريد | التنبيهات |
| رفض بنية المحتوى الناقصة | `POST /api/portfolio` |
| مصيدة بوتات (حقل مخفي `website`) + تجاهل الروبوتات في تنبيه الزيارات | `POST /api/contact` و`/api/visit` |
| `.dockerignore`: لا `.env` ولا `data/` في سياق البناء | Docker |
| التحقق من **التوقيع الفعلي** للصور (JPEG/PNG/GIF/WEBP) وليس الامتداد | `POST /api/upload-image` |
| أسماء ملفات يولّدها الخادم (`user_upload_<وقت>_<عشوائي>`) | لا مسارات من المستخدم → لا Path Traversal |
| حذف الصور يقتصر على نمط `user_upload_…` | لا يمكن حذف ملفات أخرى |
| روابط التواصل في اللوحة تقبل `http://` أو `https://` فقط | يمنع `javascript:` |
| React يهرب النصوص تلقائياً | رسائل الزوار تُعرض كنص لا HTML |

### 2.5 الأسرار
- لا أسرار في الكود ولا في `portfolio-store.json` (يُفرَّغ التوكن ومعرّف المحادثة عند كل حفظ).
- واجهة التكاملات تعرض حالة «مُهيّأ/غير مُهيّأ» فقط، دون القيم.
- `.env` خارج Git.

### 2.6 ترويسات HTTP
`X-Content-Type-Options: nosniff` · `X-Frame-Options: SAMEORIGIN` · `Referrer-Policy: strict-origin-when-cross-origin` · `Permissions-Policy` (لا كاميرا/ميكروفون/موقع) · إخفاء `X-Powered-By`.

## 3. القيود المعروفة

| القيد | الأثر | التخفيف |
| :--- | :--- | :--- |
| تحديد المعدل ورمز OTP **في الذاكرة** | يُصفَّران عند إعادة التشغيل؛ لا يعملان عبر عدة نسخ | مقبول لنسخة واحدة. للتوسع استخدم Redis |
| لا يوجد قفل حساب بعد محاولات فاشلة (فقط حد المعدل) | تخمين بطيء ممكن نظرياً | استخدم كلمة مرور طويلة جداً أو OTP فقط |
| كلمة مرور واحدة مشتركة | لا تمييز بين مديرين | مدير واحد حالياً |
| لا توجد مصادقة ثنائية | OTP عبر Telegram/بريد يعمل كعامل ثانٍ لكنه بديل لا إضافة | لو أردت 2FA حقيقية: اشترط كلمة المرور **و** OTP |
| ملفات JSON بلا قفل | كتابتان متزامنتان قد تتعارضان | مدير واحد؛ الرسائل تُعدَّل بعمليات صغيرة |
| `Content-Security-Policy` بوضع **Report-Only** فقط (يسجّل ولا يحجب) | لا حماية فعلية بعد | راجع Console على كل الصفحات ثم غيّر اسم الترويسة في `server.ts` إلى `Content-Security-Policy` |
| الكلمة الافتراضية القديمة موجودة **في تاريخ Git** | مكشوفة لمن يقرأ المستودع | **غيّر كلمة المرور فوراً** (وهي لم تعد تعمل في الكود الجديد) |
| `trust proxy = 1` | إن كانت هناك قفزتان (Cloudflare + Nginx) قد يُقرأ IP خاطئ | اضبطها حسب بنيتك |

## 4. توصيات للتحسين (بالأولوية)

1. **غيّر كل الأسرار** إن كانت قيم قديمة قد ظهرت في Git أو لقطات شاشة: `ADMIN_PASSWORD`, `SESSION_SECRET`, توكن تيليغرام (من BotFather: `/revoke`), كلمة مرور SMTP.
2. **فعّل CSP فعلياً:** السياسة موجودة بوضع Report-Only (إنتاج فقط). افتح الموقع (كل الصفحات والوضعين واللغات واللوحة) وراقب Console؛ إن لم تظهر مخالفات غيّر اسم الترويسة في `server.ts` من `Content-Security-Policy-Report-Only` إلى `Content-Security-Policy`. (إن فعّلت إضافات Cloudflare مثل Web Analytics فقد تظهر مخالفات لسكربتاتها.)
3. **فعّل HSTS** من Cloudflare (SSL/TLS ← Edge Certificates).
4. **قيّد الوصول الشبكي:** إن استخدمت Tunnel فأغلق المنفذ 3300 من الإنترنت العام.
5. **حدّ للوحة الإدارة:** قاعدة WAF في Cloudflare تقيّد `/api/verify-admin` و`/api/request-otp` على مستوى الحافة.
6. **تحديث الاعتماديات** دورياً (`npm audit`).
7. **تقليل بيانات الزوار:** الرسائل تُحفظ بلا انتهاء؛ فكّر بسياسة حذف دورية.
8. **الخصوصية والقانون (ألمانيا):** الخطوط تُحمَّل من Google Fonts مباشرة من خوادم Google، وطلبات GitHub تتم من متصفح الزائر؛ يُنصح باستضافة الخطوط محلياً، وبإضافة صفحتي **Impressum** و**Datenschutzerklärung** إن كان الموقع مهنياً/تجارياً. *(هذه ملاحظة تقنية عامة وليست استشارة قانونية؛ راجع مختصاً.)*

---

## 5. ما يجب فعله عند الشك باختراق

1. غيّر `ADMIN_PASSWORD` و`SESSION_SECRET` وأعد تشغيل الحاوية (يُبطل كل الجلسات).
2. أبطل توكن تيليغرام وكلمة مرور SMTP وأنشئ بدائل.
3. راجع `docker compose logs` (أسطر `[ADMIN AUTH]`) و`data/*.json` والصور المرفوعة `user_upload_*`.
4. استعد المحتوى من نسخة احتياطية أو بزر «Restore Default CV».
