# 8️⃣ الصيانة والتطوير والمشاكل المعروفة

## 1. وصفات التطوير الشائعة

### 1.1 إضافة مشروع تجريبي
**من لوحة الإدارة:** Projects ← Add Project ← ارفع صورة، املأ العناوين والوصف بالثلاث لغات، التقنيات، رابط العرض ← Save Project.
**من الكود:** أضف كائناً في `projects` داخل `src/data.ts` ثم ارفع `dataVersion`. ضع صورته في `public/images/` (وليس `src/assets/images/` بسبب فخ الوحدة).

> اكتب الوصف والنتيجة كإمكانيات للمشروع التجريبي، لأن الصفحة تقدّمه بوضوح كمشروع شخصي (Demo).

### 1.2 إضافة وظيفة جديدة في الخبرات
Experiences ← Add Experience. اكتب كل نقطة في سطر مستقل. إن أردت تبويباً مستقلاً لشركة جديدة عدّل `getFilteredExperiences` ومصفوفة التبويبات في قسم `#experience`.

### 1.3 تحديث ملفات السيرة PDF
استبدل `public/Amro_Nazzal_CV_EN.pdf` و`public/Amro_Nazzal_Lebenslauf_DE.pdf` بنفس الاسم، وانشر. (لا يوجد PDF عربي؛ العربية عبر «عرض» و«طباعة».) وقد يبقى الملف القديم في كاش Cloudflare → Purge.

### 1.4 تغيير النطاق (Domain)
عدّل في `index.html`: `canonical`، `og:url`، `og:image`، `twitter:image`، وحقل `url` و`image` في JSON-LD. وفي `public/og-image.png` النص إن لزم.

### 1.5 تغيير صورة المعاينة (Open Graph)
استبدل `public/og-image.png` بصورة 1200×630. بعد النشر استخدم أدوات إعادة الزحف (LinkedIn Post Inspector / Facebook Sharing Debugger) لتحديث الكاش.

### 1.6 إضافة متغير بيئي
1. أضفه في `.env.example` و`.env`.
2. مرّره في `docker-compose.yml` تحت `environment`.
3. اقرأه في `server.ts` بـ `process.env.NAME`.
4. أعد بناء الحاوية.

### 1.7 إضافة مسار API جديد
1. في `server.ts` قبل قسم الملفات الثابتة.
2. إن كان إدارياً أضف `requireAdmin`؛ وإن كان عاماً أضف `rateLimit(...)` وتحققاً صارماً من المدخلات.
3. استدعِه من الواجهة بـ `adminFetch` (إداري) أو `fetch` (عام).

### 1.8 إضافة لغة أو قسم أو مفتاح ترجمة
انظر `02-frontend.md` (القسمان 3 و10).

### 1.9 تغيير حدود الصور
- الحد الأقصى في الخادم: `server.ts` ← `/api/upload-image` (5MB).
- أبعاد التصغير في المتصفح: `resizeImageToDataUrl(file, maxDim = 1400, quality = 0.86)` في `App.tsx`.

## 3. اختبار يدوي سريع (قبل أي نشر)

### الواجهة العامة
- [ ] الصفحة تُحمَّل بلا أخطاء في Console (جرّب EN / عربي / DE).
- [ ] العربية: الاتجاه RTL، التواريخ بالترتيب الصحيح (`02.2024 - 08.2026`).
- [ ] اللغة: `?lang=de` يفتح الألمانية؛ بعد اختيار لغة يدوياً تبقى عند إعادة الفتح.
- [ ] التمرير: القسم الحالي يتمّيز في القائمة.
- [ ] الوضع الداكن والفاتح.
- [ ] الموبايل: شريط الأقسام يتمرر، أزرار 44px، لا تمرير أفقي للصفحة.
- [ ] قسم الخبرات: يظهر 3 فقط ثم «عرض الوظائف السابقة».
- [ ] المشاريع: شارة Demo، الأزرار تفتح الروابط.
- [ ] GitHub: تظهر المستودعات.
- [ ] نموذج التواصل: رسالة صحيحة ✔، بريد خاطئ ✖ (رسالة خطأ)، 6 رسائل متتالية ← الأخيرة `429`. (الحقل المخفي `website` يبقى فارغاً).
- [ ] السيرة: عرض/طباعة بالثلاث لغات، تنزيل EN وDE.

### لوحة الإدارة (`/#admin`)
- [ ] دخول بكلمة المرور، ودخول بـ OTP.
- [ ] كلمة مرور خاطئة ← رسالة خطأ.
- [ ] Profile: تغيير الصورة ← معاينة ← Save ← تظهر في الموقع (وتُحذف السابقة المرفوعة).
- [ ] ملف ليس صورة ← يُرفض.
- [ ] تعديل نبذة ولغات وموقع، مسح رابط اختياري (يختفي الزر).
- [ ] إضافة/تعديل/حذف خبرة ومشروع ومؤهل.
- [ ] Skills: تعديل ثم Cancel ← لا يتغير شيء.
- [ ] Integrations: الحالة صحيحة، أزرار الاختبار تعمل، الحفظ.
- [ ] Inbox: تحديث، مقروء، حذف.
- [ ] Restore Default CV ← المحتوى الافتراضي، **الرسائل باقية**.
- [ ] انتظر انتهاء الجلسة أو حدّث الصفحة ← يطلب الدخول مجدداً.

### الخادم
- [ ] `npm test` ← `# fail 0`.
- [ ] `npm run lint` بلا أخطاء.
- [ ] `npm run build` ينجح.
- [ ] `docker compose up -d --build` ثم `docker compose ps` = healthy.

## 4. اصطلاحات الكود (للمساهمة)

- TypeScript صارم الأنواع للبيانات (`types.ts`)؛ أي حقل جديد في المحتوى يُضاف هناك أولاً ثم `data.ts` ثم الواجهة، **وارفع `dataVersion`**.
- كل نص ظاهر للزائر بثلاث لغات.
- استخدم خصائص Tailwind المنطقية (`ps/pe/ms/me/start/end`) لا `left/right`.
- لا تضع أسراراً في الكود أو في المحتوى المخزّن.
- كل مسار API إداري يجب أن يمر عبر `requireAdmin`، وكل مسار عام عبر `rateLimit` وتحقق مدخلات.
- لا تعتمد على `src/assets/images/` للصور الثابتة الجديدة؛ استخدم `public/`.
