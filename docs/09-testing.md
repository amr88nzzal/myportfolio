# 9️⃣ الاختبارات الآلية (Testing)

المشروع يحتوي **28 اختباراً آلياً** تعمل بأداة الاختبار المدمجة في Node (`node:test`) بلا اعتماديات إضافية.

## 1. التشغيل

```bash
npm test
```

(الأمر الفعلي: `node --import tsx --test tests/*.test.ts` ويتطلب Node 20.6 أو أحدث، و`tsx` موجود ضمن `devDependencies`.)

نتيجة النجاح تنتهي بـ `# fail 0`. أي اختبار فاشل يُظهر اسمه والقيمة المتوقعة والفعلية.

## 2. ماذا تغطي؟

### `tests/utils.test.ts` — منطق الخادم (`backend/utils.ts`)
| الاختبار | ما يتحقق منه |
| :--- | :--- |
| `safeEqual` | مقارنة الأسرار (متساوية، مختلفة، طولان مختلفان) |
| `escapeHtml` | تحييد `< > & "` و`null` |
| `EMAIL_PATTERN` | عناوين بريد صحيحة وخاطئة |
| جلسات الإدارة | توكن صالح / معدّل / منتهي / بسر مختلف / نصوص عشوائية |
| محدّد المعدل | الحد، زمن الانتظار، انزلاق النافذة، استقلال المفاتيح، عدم تمديد الحظر، تنظيف الذاكرة |
| `detectImageType` | JPEG/PNG/GIF/WEBP الحقيقية، ورفض سكربت PHP أو SVG بامتداد صورة |
| `UPLOAD_NAME` | قبول أسماء الرفع فقط، ورفض `../` والامتدادات الأخرى |
| `referencedImageFiles` / `orphanedUploads` | حذف الصور المرفوعة المستبدلة **فقط**، وعدم لمس الصور الافتراضية أو المستخدمة |
| `sanitizeTelegramToken` | استخراج التوكن من رابط أو نص، وعدم إفساد توكن يحتوي حروف `bot` (خطأ قديم أُصلح) |
| `isBotUserAgent` | الزواحف والأدوات مقابل المتصفحات |

### `tests/helpers.test.ts` — الواجهة (`src/lib/helpers.ts`)
`isProfileUrl` واختيار اللغة عند أول زيارة (الرابط ← المحفوظ ← المتصفح ← الإنجليزية) مع قيم غير صالحة وتخزين محجوب.

### `tests/content.test.ts` — سلامة المحتوى
- مفاتيح الترجمة **متطابقة** في en/ar/de وغير فارغة، والمتغيرات `{name}` و`{subject}` موجودة.
- كل نص في `data.ts` موجود بالثلاث لغات، وعدد النقاط متساوٍ بين اللغات.
- المعرّفات فريدة، وصيغة الفترات `MM.YYYY - MM.YYYY`، ومستويات المهارات 1–5.
- روابط المشاريع `https://`، وملفات صورها **موجودة فعلاً**، ولا يدّعي نص المشروع أرقام إنتاج (لأنها مشاريع Demo).
- ملفات السيرة PDF وصورة المعاينة وصورة الشخصية موجودة.
- تبويبات الخبرات (`bmw` / `sahli` / `aljawaden` / المحاسبة) ما زالت تطابق بيانات فعلية.

> هذه الاختبارات اكتشفت فعلاً أن روابط المشاريع كانت `http://` فصُحّحت.

## 3. كيف تضيف اختباراً؟
1. أنشئ ملفاً `tests/<name>.test.ts`.
2. استورد من `node:test` و`node:assert/strict` وما تريد اختباره (مثل `../backend/utils`).
3. اكتب `test('وصف', () => { assert.equal(...) })` ثم شغّل `npm test`.

**قاعدة:** أي منطق جديد في الخادم يُوضع في `backend/` كدوال نقية (بدون Express) ليسهل اختباره. ما يحتاج `express` أو الشبكة يبقى في `server.ts`.

## 4. ما لا تغطيه الاختبارات (قيود)
- **لا اختبارات واجهة (Component/E2E):** لا يُختبر رسم الصفحة ولا لوحة الإدارة ولا RTL ولا الموبايل. يلزم اختبار يدوي (انظر قائمة التحقق في `08-maintenance-and-known-issues.md`) أو إضافة Playwright لاحقاً.
- **لا اختبار لمسارات Express نفسها** (الحماية `requireAdmin`، الردود، الحدود). الحلقة بين المسار والدوال النقية غير مغطاة.
- **لا تختبر الخدمات الخارجية** (Telegram وSMTP وGitHub).
- **جودة الترجمة نفسها** لا يمكن اختبارها آلياً؛ الاختبار يضمن الوجود والتطابق فقط.

## 5. اقتراح: تشغيلها تلقائياً
أضف ملف GitHub Actions (`.github/workflows/ci.yml`) يشغّل عند كل push: `npm install --legacy-peer-deps` ثم `npm run lint` ثم `npm test` ثم `npm run build`. (لم يُضَف تلقائياً لأن `npm run lint` لم يُشغَّل هنا، وقد يكشف أخطاء أنواع تحتاج إصلاحاً أولاً.)
